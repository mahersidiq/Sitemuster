# 03 — Native location engine, offline ownership, and privacy

## Exact implementation choice

Use **Transistorsoft `react-native-background-geolocation` v5** via Expo native development builds and its first-party config integration. Not browser geolocation, React JS interval timers, or plain Expo location background task as the primary tracker. Verify supported SDK config keys against the installed v5 type definitions, then pin versions at Milestone 01. Native SDK queue owns **only location/geofence records**; `expo-sqlite` owns other offline operations. `docs/spec/11-api-contracts.md` defines the native HTTP contract.

**Native baseline:** `stopOnTerminate:false`, `startOnBoot:true`, `enableHeadless:true` (Android), native HTTP `batchSync:true`, `maxBatchSize:25`, autoSync true, custom device credential header, HTTPS only, geofence-only mode offsite. Target iOS `DesiredAccuracy.High`, `distanceFilter:25m`, `activityType:Fitness`, `pausesLocationUpdatesAutomatically:true`, `showsBackgroundLocationIndicator:true`, proper `UIBackgroundModes.location`. Android location foreground-service mode/notification when continuous onsite mode applies; never claim force-stop recovery.

## Two-mode engine

**Native fence geometry (resolves exit-check vs privacy conflict):** each project registers ONE native circular geofence of radius `geofence_radius_m + exit_hysteresis_m` (default 150 + 50 = 200 m). Because the hysteresis is built into the native fence, a native EXIT already means "left the buffered boundary" and needs no coordinates to corroborate. Entry qualification still uses the inner `geofence_radius_m` evaluated from the two qualified onsite fixes. One region per project, so the iOS 15-region budget is unchanged.

**ARMED_OFFSITE:** monitor relevant circular project geofences with `startGeofences()`, without continuous location collection/onsite map feeds; do not transmit or persist ongoing offsite coordinates. Use a **geofence payload template with UUID, timestamp, identifier, ENTER/EXIT and no lat/lng**, so geofence exit never sends offsite coordinates. Only necessary local geofence check uses location. Disable provider-change synthetic coordinate uploads. Do not use root params to inject worker/project identity as authoritative; server derives from upload token and geofence identifier which is scoped to that device.

**ENTRY_PENDING:** collect two accuracy-qualified inside fixes at least 10 min apart with 75m maximum stated horizontal accuracy. Only transmit coordinates if the **on-device boundary gate** and permission/consent are satisfied. For ambiguous area/overlapping geofences, record status only, do not upload potential offsite coordinates or count automatically. If a device cannot guarantee the SDK's raw native HTTP body omits unapproved fixes (including delayed callback/killed app), **continuous coordinates must be disabled**; keep geometry-free geofence event metadata and no-phone fallback. This is a release-blocking privacy assertion that must be demonstrated with network/HTTP trace tests on real iOS/Android builds.

**ONSITE_ESTIMATED:** once dwell and permitted session established, use battery-aware motion-sensitive sampling. Moving target 90 seconds, stationary target 5 min, 25m distance filter, five-minute stationary timeout. These are sampling goals, not guaranteed periodic background wakeups. On qualified EXIT, stop onsite continuous recording as soon as platform allows; geofence event template remains coordinate-free; never forward raw exit coordinates. Clear latest worker location visibility after departure or revocation.

**WARNING:** Native `locationTemplate` is static and does not itself compute polygon or site-boundary authorization. Do not assume the SDK automatically removes offsite coordinates from raw uploads. Design a native-side egress filter or audited two-mode configuration that guarantees the privacy rule in real device traces. If not verifiable, turn OFF the raw coordinate uploader/continuous location feature, show `TRACKING_LIMITED`, and retain entry/exit metadata + fallback rather than quietly violating privacy. Backend discarding coordinates is NOT equivalent to preventing transmission.

## Device account, credential and locked-phone operation

- One active personal tracking device per worker. Register device with verified worker session + server-authorized project; create cryptographically secure 32-byte bearer secret, store SHA-256 hash only in DB, scope to one active worker/device/project binding. Device is registered to multiple authorized project geofences through server associations, but ingestion resolves each identifier against the credential's allowed enrollment set; **never** let credential specify arbitrary project ID. (If implementation issues separate per-project credentials, each remains project scoped.)
- Upload bearer credential validity 30d; revoke on new phone, logout, consent removal or membership loss. **Workers whose tracking works never need to open the app, so foreground-only renewal would silently kill tracking around day 30 for the best users.** Renewal paths, in order: (1) app foreground with <=7d left; (2) silent/background push (`content-available` iOS, data message Android) sent by server at <=7d left that triggers a headless renew where the OS allows; (3) Transistorsoft heartbeat/headless task opportunistic renew where the OS allows; (4) visible localized push at 7d, 3d and 1d left: "Open SiteMuster to keep automatic attendance on". None of these is guaranteed; therefore server also flags `CREDENTIAL_EXPIRING` (<=3d) and `CREDENTIAL_EXPIRED` on the superintendent roster so the foreman can ask the worker to open the app.
- After ANY successful renew: call `BackgroundGeolocation.setConfig({ http: { headers: { Authorization: 'Bearer <new>' } } })` BEFORE the next sync, persist new token in SecureStore, and keep the previous token valid server-side for a 24h overlap (`rotated_from`) so a batch already in flight with the old header is not lost. Test: renew mid-queue with 25 pending records ⇒ zero loss, zero duplicates. If expired, SDK receives 401, stops authorized upload; mark status unavailable and reconcile on foreground. Do not silently collect an indefinite local queue on an invalid credential.
- `expo-secure-store` key access `AFTER_FIRST_UNLOCK` on iOS, no `requireAuthentication` for background key; large Supabase session encrypted AES-256-GCM (`@noble/ciphers`) in SQLite with key from SecureStore. Validate ciphertext format, IV uniqueness, key rotation, device-lock behavior. No session stored in SecureStore exceeding platform limits. Never require JS/Supabase session refresh to transmit a queued native event.
- Native SDK queue holds durable event payloads; no duplicate in expo-sqlite operational outbox. Both queue counts flow to one Sync Status UI, with per-queue error details. Server event idempotency via unique UUID.

## Recovery and geofence scheduling

- On initial ARM, re-ARM, project boundary revision, app foreground, eligible device boot recovery, and after sync if latest qualified fix >5 min old, request current qualified fix to handle already-inside without waiting for ENTER. Preserve first actual observed fix time; no synthetic backdating.
- iOS OS cap 20 monitored regions; our target 15 native active. Android native target 75 (limit typically ~100). Transistorsoft proximity scheduler may store many geofences but does not remove OS limits. If subscriptions exceed coverage, prioritize current assignment, proximity and upcoming scheduled shifts; display not-monitoring statuses for other assignments.
- Handle iOS OS-managed relaunch after termination/reboot; Android headless boot only when platform permits. No claims of recovery from Android Settings Force Stop, OEM killing, user permission withdrawal, iOS force quit or device turned off.
- Overlapping projects: never auto-count both. Use `AMBIGUOUS_PROJECT` and request user/attendant choice with server validation; account for potentially shared phone.

## Permissions and platform policies

**iOS:** first When In Use, then justified Always upgrade; reject Reduced Accuracy for GPS auto-attendance; `NSLocationWhenInUseUsageDescription`, `NSLocationAlwaysAndWhenInUseUsageDescription`, iOS background mode `location`, motion usage description when needed. Explain periodic Apple background-use notices and blue indicator. If permission removed or Precise disabled, set MONITORING_UNAVAILABLE; kiosk/foreman remains usable.

**Android:** Android 10+ background request distinct; Android 11+ settings instructions; Android 12+ precise toggle required for automatic GPS attendance; Android 13+ notification permission; Android 14+ `FOREGROUND_SERVICE_LOCATION` and `location` type with ongoing visible notification when using continuous tracking foreground service. Permission/foreground-service restrictions may prevent automatic starts from background; status must reflect that. Provide Play Console declaration and demonstrative video.

## Privacy assertions

- A site event must be linked to versioned approved project consent. `accepted_at`, `version_id`, `locale`, `worker_id`, `project_id` must be verifiable.
- No raw offsite coordinate on HTTP request, in server logs, Sentry, push, Realtime, or operator analytics. Do not log raw SDK payloads in production.
- Native SDK uploaded geofence event never includes coordinates; raw onsite fixes go only during qualified authorized onsite mode. Post-exit payloads must not leak in in-flight batches; test network traces in field.
- `latest_onsite_positions` used for map only when fresh, authorized; mark stale after 10 min, presence unknown after 20 min without better attendance evidence; these thresholds do not imply departure.
- Raw fixes must be deleted within 24h after session closure; for unresolved sessions run separate limited 24h freshness purge and preserve only non-coordinate attendance metadata. Worker deletion follows `09-security-privacy.md`.

## Device validation matrix

Test iPhone and Android: foreground, background, app force-close, reboot, first unlock, missed region, already inside, permission changed, reduced/approximate, adjacent projects, poor GPS, airplane mode, vehicle pass-through, battery savings, overnight idle, false boundary bounce, SMS logout/re-login, replacement device. Simulator/replay results cannot substitute for real device proof.
